# Learning Phase Documentation Skill

1. Read `docs/learning/PHASE-WORKFLOW.md` and `docs/learning/PHASE-TEMPLATE.md`.
2. Keep the learner's agreed phase boundary. Do not jump to later phases.
3. Prefer official documentation; add videos only when they provide clear value.
4. Record exact commands in execution order and explain what each does and why.
5. Distinguish expected output from output that has actually been verified.
6. Record files changed, prerequisites, version checks, troubleshooting, exercises, review questions, and completion criteria.
7. Use clear English technical terms alongside natural Arabic explanations where appropriate.
8. Do not claim that a step was run unless the user or agent actually ran it.
9. Update the phase guide after implementation so it reflects the final repository state.
10. Stop at the completion gate and ask the learner to approve the next phase.
